## 1. Context

What was true when this was decided. Cite repository evidence with `file.py:line`,
commits as backticked SHAs, and documents as relative links. Numbers must be measured,
not recalled — say where each came from.

Mark anything unverified as unverified. A record that quietly mixes measured and
assumed figures is worse than one that omits the assumed ones.

## 2. Decision

State it in the imperative, in a few sentences. If the decision has parts that could
be accepted separately, number them so a later ADR can supersede one part without
reopening the rest.

## 3. Evidence

The measurements the decision rests on, as a table where possible. Include the ones
that argue *against* the decision — a record that only lists supporting evidence is an
advertisement.

## 4. Alternatives rejected

| Alternative | Why it lost |
|---|---|

One row per real option. "Do nothing" is a real option and usually belongs here.

## 5. Consequences

What this costs, not only what it buys. Include work this creates elsewhere, tests
that will break, and anything that becomes harder to reverse.

## 6. Revisit trigger

The observation that would reopen this decision, stated so that someone else could
check it without asking the author. Prefer evidence over time where both work: a
time-box can pass while nothing has been learned. AMENDMENT A4 of the corpus-ledger
spec records a stopping rule that failed review three independent ways, any one fatal
— it was a conjunction passable by deleting dead code, its second clause could only be
satisfied by theatre, and it measured the wrong store. A trigger that cannot fire is
the same defect in a different costume.

When it fires, write a new ADR that supersedes this one. Do not edit this file except
to add its `Superseded by:` line.
